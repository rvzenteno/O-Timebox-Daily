# Timebox v1.6 Capability Gap Analysis: Desktop PM Benchmark

**Date**: 2026-09-16  
**Baseline Version**: Timebox 1.5.0 (Frozen Production Baseline)  
**Status**: Formal Product Discovery & Capability Evaluation  
**Objective**: Rigorous evaluation of Timebox v1.5 against capabilities expected in mature desktop project-management software (Microsoft Project, ProjectLibre, Primavera P6, OmniPlan).

---

## Evaluation Classification Schema

Each capability is classified into exactly one of four objective tiers without arbitrary numeric scores:

- **IMPLEMENTED**: Fully supported, architecturally verified, and covered by automated test suites.
- **PARTIAL**: Basic engine or UI capability exists, but key workflows, fields, or presentation ergonomics remain incomplete.
- **MISSING**: Recognizable desktop project management capability not currently implemented in Timebox.
- **NOT APPLICABLE**: Capability that fundamentally contradicts Timebox's local-first Markdown architecture or dual-layer design principle.

## 1. Scheduling

| Capability | Benchmark Standard (MS Project / P6) | Timebox v1.5 Status | Implementation Analysis & Notes |
|:---|:---|:---:|:---|
| **Forward Pass Scheduling** | Early Start/Finish calculation from project start | **IMPLEMENTED** | Full topological 2-pass CPM engine with working calendar awareness. |
| **Backward Pass Scheduling** | Late Start/Finish calculation from project deadline | **IMPLEMENTED** | Calculates latest dates without delaying deadline. |
| **Fixed Duration Tasks** | Duration invariant; work adjusts with resource units | **IMPLEMENTED** | Duration drives calendar days; work calculated via duration $\times$ hours $\times$ units. |
| **Milestones Calculation** | Zero-duration checkpoints (`0d`) | **IMPLEMENTED** | Point-in-time calculation; start equals finish; zero work. |
| **Summary Task Rollup** | Recursive phase dates, duration, work, and progress | **IMPLEMENTED** | Bottom-up rollup across arbitrary WBS nesting depth. |
| **Effort-Driven Scheduling** | Work is invariant; adding resources shortens duration | **PARTIAL** | Work dynamically calculated; automatic duration compression on assignment change not yet implemented. |
| **Fixed Work Tasks** | Work invariant; duration derives from units | **MISSING** | Currently, duration is primary input; fixed-work task type flag not available. |
| **Sub-Day / Hourly CPM** | Fractional day dependencies (e.g. 2.5 hours lag) | **NOT APPLICABLE** | Intentionally excluded to protect macro calendar clarity. Intraday scheduling belongs in daily timeboxes. |

## 3. Critical Path / CPM

| Capability | Benchmark Standard (MS Project / P6) | Timebox v1.5 Status | Implementation Analysis & Notes |
|:---|:---|:---:|:---|
| **Early Dates (ES, EF)** | Earliest possible task execution dates | **IMPLEMENTED** | Computed during forward CPM pass. |
| **Late Dates (LS, LF)** | Latest allowable execution dates without slippage | **IMPLEMENTED** | Computed during backward CPM pass from project deadline. |
| **Total Float (TF)** | Permissible task slip before project finish slips | **IMPLEMENTED** | $TF = LS - ES = LF - EF$. Displayed in Task Sheet and tooltips. |
| **Free Float (FF)** | Permissible task slip before successor slips | **IMPLEMENTED** | Computed as minimum successor early start minus task early finish. |
| **Critical Path Highlighting**| Visual designation of driving sequence | **IMPLEMENTED** | `⚡ Critical Path` button highlights $TF \le 0$ tasks in Gantt and Summary. |
| **Multiple Critical Paths** | Divergent zero-float parallel chains | **IMPLEMENTED** | Supported naturally through DAG float calculations. |
| **Near-Critical Path Analysis**| Highlighting tasks with float $\le \text{threshold}$ | **MISSING** | Fixed check on $TF \le 0$; user-configurable near-critical float threshold missing. |
| **Driving Predecessor Audit** | Explicit indicator of which predecessor drives ES | **MISSING** | Computed in engine logic, but not surfaced as dedicated UI column/indicator. |
